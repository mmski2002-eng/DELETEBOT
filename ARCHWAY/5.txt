# PROMPT 4 — Callbacks / CWFeeGrants / CWICA / CWErrors audit

Ты — security research agent для легального bug bounty / responsible disclosure.
Работай только с локальным кодом, локальными тестами, локальной сетью или testnet. Не предлагай эксплуатацию mainnet, DoS публичной сети, кражу средств или действия против чужой инфраструктуры.

Цель: проверить callback, fee grant, interchain account и error-handling логику в Archway.

Контекст:
Самые частые баги в такой зоне появляются на границах:
- async callback;
- IBC ack/timeout;
- retry;
- failed callback;
- wrong payer;
- refund;
- replay;
- swallowed errors;
- unexpected partial state;
- fee grants draining;
- ICA unauthorized execution.

Сначала найди файлы и функции по ключам:
`callback`, `callbacks`, `feegrant`, `cwfeegrant`, `ica`, `interchain`, `ack`, `acknowledgement`, `timeout`, `packet`, `reply`, `sudo`, `error`, `cwerrors`, `refund`, `payer`, `grant`, `allowance`.

Вопросы аудита:

1. Callback lifecycle
- Как регистрируется callback?
- Кто может его зарегистрировать?
- Как callback вызывается?
- Что происходит при success?
- Что происходит при error?
- Что происходит при timeout?
- Можно ли callback вызвать повторно?
- Можно ли replay old callback?
- Удаляется ли callback state корректно?

2. IBC / ICA
- Проверяется ли channel/port/connection?
- Проверяется ли counterparty?
- Проверяется ли sequence?
- Что происходит при ack error?
- Что происходит при timeout?
- Есть ли duplicate handling?
- Есть ли replay protection?
- Может ли чужой контракт получить результат чужого interchain action?

3. Fee grants
- Кто payer?
- Кто grantee?
- Можно ли заставить другого payer оплатить tx?
- Можно ли drain fee grant?
- Что происходит при failed execution?
- Есть ли refund?
- Есть ли mismatch между expected fee и actual fee?
- Проверяется ли allowance/cap/expiration?

4. CWErrors
- Ошибки пробрасываются или swallowing?
- Может ли swallowed error привести к successful state?
- Есть ли разница между contract error и module error?
- Есть ли panic/recover paths?
- Может ли ошибка в callback оставить funds/rewards stuck?

Ищи:
- replay / double execution;
- unauthorized callback;
- wrong receiver;
- wrong payer;
- fee grant draining;
- refund bug;
- stuck state after failed callback;
- ack/timeout mismatch;
- swallowed error changing security assumptions;
- incorrect state after partial failure.
