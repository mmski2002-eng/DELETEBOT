Построй карту cross-chain поверхности:

1. Какие bridge/IBC routes поддерживаются?
   - source chain
   - destination chain
   - channel id
   - port id
   - ordering
   - status
   - operators/relayers if present
   - frontend/API config if present

2. Какие user-controlled поля входят в transfer?
   - sender
   - receiver
   - amount
   - denom
   - memo
   - timeout height
   - timeout timestamp
   - channel
   - route
   - destination chain
   - slippage / swap params if present

3. Для каждого flow опиши state machine:
   - source-side debit
   - packet creation
   - relay
   - destination-side credit/execute
   - acknowledgement
   - timeout
   - refund
   - retry
   - failed acknowledgement
   - frontend status update

4. Ищи следующие классы багов:
   - funds debited but never refundable
   - refund possible after successful execution
   - duplicate ack / duplicate refund
   - timeout and success both accepted
   - wrong receiver due to memo parsing
   - memo injection into downstream app
   - stale channel config causing funds loss
   - denom trace mismatch
   - decimal mismatch
   - frontend route mismatch
   - wrong chain id / channel id pair
   - cross-chain swap partially executed
   - relayer assumes packet success without verifying ack
   - API marks tx complete before final destination state
   - bridge UI lets user construct unsafe transaction
   - transfer to contract/account confusion
   - blocked/module address receiver edge cases

5. Для Axelar-specific анализа:
   - Найди integration code/config for Axelar.
   - Проверь, есть ли GMP, Squid, Satellite, gateway, ITS, wrapped assets или только IBC transfer.
   - Не делай вывод, что Archway поддерживает GMP, пока не найдёшь код/доки.
   - Сравни actual supported route с frontend assumptions.
   - Проверь, нет ли mismatch между Axelar chain name, Cosmos chain id, channel id, denom, asset symbol.

6. Для Balanced/xCall-specific анализа:
   - Найди code/config/docs для Archway connection.
   - Построй flow ICON ↔️ Archway.
   - Проверь xCall message verification, source chain validation, destination contract validation, serial number / nonce / sequence.
   - Проверь failed swap, failed transfer, timeout, duplicate message, retry, refund.
   - Особое внимание: sARCH/bnUSD, liquidity held on ICON, cross-chain transfer to Archway.

7. Не считать хорошей находкой:
   - “relayer can censor” без конкретного loss-of-funds impact;
   - stale UI без fund-loss или severe UX/security impact;
   - известную IBC особенность без Archway-specific route impact;
   - проблему, требующую контроля majority validators;
   - mainnet-only эксперимент без локального PoC.
